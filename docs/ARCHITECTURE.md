## Overview

A personal portfolio site for a brand and visual designer. It is a **Next.js 15
static export** (`output: 'export'`) - there is no server at runtime, no API, and
no database. `next build` emits plain HTML/CSS/JS into `out/`, and Netlify
publishes that directory.

Two sites live in this one repo, and confusing them is the single most common
mistake here:

1. **The Next.js app in [`app/`](../app/)** - this is what deploys and what
   matters. App Router, five routes, authored in Tailwind v4 utility classes.
2. **A legacy hand-written static site** at the repo root
   ([`index.html`](../index.html), [`gallery/`](../gallery/),
   [`projects/*.html`](../projects/)) - retained, still tracked, **not deployed**.
   It is the only consumer of the committed [`style.css`](../style.css).

```
                    ┌──────────────────────────────────────────┐
  source            │ app/            brand.css   src/css/     │
                    │ (App Router)    (tokens)    (reset,      │
                    │                             preset)      │
                    └───────┬──────────────────────┬───────────┘
                            │                      │
              app/globals.css                  app.css
              (Next PostCSS)                (Tailwind CLI)
                            │                      │
                            v                      v
                    ┌───────────────┐      ┌──────────────┐
                    │ next build    │      │ style.css    │
                    │   -> out/     │      │ (committed)  │
                    └───────┬───────┘      └──────┬───────┘
                            │                     │
                            v                     v
                    ┌───────────────┐      ┌──────────────────┐
                    │ Netlify       │      │ legacy root site │
                    │ (publish=out) │      │ NOT deployed     │
                    └───────────────┘      └──────────────────┘

  runtime (browser, no server):
    theme-init.js  -> stamps data-theme on <html> before paint
    bubbles.js     -> DOM physics engine, exclusion zones
    history-of-mistrust-slideshow.js -> case-study carousel + lightbox
```

**Two CSS entry points compile the same sources.** `app/globals.css` (Next's
PostCSS pipeline) governs what deploys; `app.css` (Tailwind CLI) produces the
committed `style.css` for the legacy site. Both import `brand.css` into the
`components` layer so utilities can override it. Editing one and not the other is
a real failure mode.

## Execution Model

There is no server. Everything is a build step or browser runtime.

| Command | What it does |
|---|---|
| `npm run dev` | `next dev` on :3000. The real app, hot reload. **The dev/preview surface during the deploy pause.** |
| `npm run build:next` | `next build` -> static export into `out/`. |
| `npm run css:build` | Tailwind CLI, `app.css` -> `style.css` (minified). Legacy site only. Commit the rebuilt file. |
| `npm test` | Playwright: 55 tests (smoke + 40 visual baselines + 10 bubble specs). |
| `npm run serve` | `serve . -l 8080` - **legacy root site only**, not the Next app. |

**Build ordering trap:** `distDir` is `out`, so `build:next` deletes and recreates
the directory a running `next dev` is serving from. Never run them concurrently -
every route starts 500ing with `ENOENT .../out/routes-manifest.json`.

**Browser runtime**, all in [`public/scripts/`](../public/scripts/):

- `theme-init.js` - loaded via `<Script strategy="beforeInteractive">` from
  [`app/layout.tsx`](../app/layout.tsx). Stamps `data-theme` on `<html>` before
  first paint so there is no theme flash. It **must render inside `<body>`**; as
  a direct child of `<html>` React throws a hydration error on every load.
- `bubbles.js` - DOM-based physics engine. Bubbles avoid *exclusion zones*
  resolved by CSS selector from `DEFAULT_EXCLUSIONS` (includes the semantic
  `.bubble-exclude` marker), `HOME_EXCLUSIONS`, and per-page `data-exclusions`.
  Exposes `window.__bubbleEngine` for tests. **Duplicated** at
  [`scripts/bubbles.js`](../scripts/bubbles.js); `public/` is the served copy.
- `history-of-mistrust-slideshow.js` - the case-study carousel, its lightbox, and
  the `SLIDE_ALT` caption/alt-text array.

**Deploy flow:** push `portfoliowebsite` -> Netlify runs `next build` -> publishes
`out/`. A docs-only push is cancelled by the `[build] ignore` rule in
`netlify.toml`. Deploys are **credit-metered, not minute-metered** (15 credits per
production deploy, 300/month). Full rules: [`deploys.md`](deploys.md).

## Data / Config Model

No database, no ORM, no migrations. "Data" is TypeScript literals and image trees.

| Store | Location | Shape |
|---|---|---|
| Gallery items | [`app/gallery/gallery-data.ts`](../app/gallery/gallery-data.ts) | `GalleryItem[]` = `{ src, alt, caption, width, height, tags, tools, description }`. `tags` (Digital/Traditional) drive the filter and render `sr-only`; `tools` is the visible middot-separated line; `description` is populated as `''` on every item and **is not rendered yet** - it awaits user copy. |
| Project case studies | [`app/projects/BrandProject.tsx`](../app/projects/BrandProject.tsx), [`MistrustProject.tsx`](../app/projects/MistrustProject.tsx) | JSX, not data. No tag system on this page. |

| Share card | [`app/og.ts`](../app/og.ts) | One `{ url, width, height, alt }` object consumed by all four pages. |

Notes on the pins that matter:

- **Tailwind v4** (`@tailwindcss/cli` + `@tailwindcss/postcss`). v4 uses
  `@import "tailwindcss"` and `@source` directives, not a `tailwind.config.js`.
  The `@source not "**/*.md"` exclusions are load-bearing: without them the class
  scanner reads `LOGBOOK.md`/`TODO.md` and a class merely *mentioned* in prose is
  compiled back into the shipped CSS.
- **`sharp`** is used only by the generator scripts (webp encoding, og downsample),
  never at runtime.
- **`serve`** backs both `npm run serve` (legacy, :8080) and the Playwright test
  server (:4322, started in global setup).
- **Playwright** is pinned off Netlify with `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1` -
  CI never runs the suite. Adding a test step to the build command means dropping
  that variable first.
- The lockfile is committed; `node_modules/` is not.

## Testing Model

One Playwright suite, three kinds of test, **55 total**:

| Kind | File | What it proves |
|---|---|---|
| Smoke | `smoke-next.spec.js`, `smoke-interaction.spec.js` | Each route loads without console errors; tab switch and lightbox work. |
| Visual gate | `visual-baseline.spec.js` | 40 snapshots = 5 pages x 4 breakpoints (360/768/1024/1440) x 2 themes. A real compare gate, not capture-only. |
| Bubble engine | `bubbles-exclusion.spec.js` | 10 specs. **The only motion-enabled spec** - the visual gate runs under `prefers-reduced-motion`, where the engine creates nothing. |

Smallest useful commands: `npx playwright test -g "<name>"` for one case,
`npx tsc --noEmit` for types, `npm run css:build` for the legacy stylesheet
(expect byte-identical output if nothing changed).

Three harness facts that are easy to break and cost a cycle each:

- `next build` runs in **`tests/global-setup.js`**, not in `webServer.command` -
  `reuseExistingServer` skips the command when the port is held, which made the
  suite grade a stale `out/`.
- Reduced motion is applied with `page.emulateMedia()`, **not**
  `test.use({ reducedMotion })` - the declarative option is silently ignored on
  Playwright 1.61.1.
- `bubbles-exclusion.spec.js` runs `mode: 'serial'` **on purpose**. The engine
  integrates per frame, so concurrent runs starve rAF and leave bubbles grazing
  zone edges, which reads exactly like a real regression.

To accept an intentional visual change: `npm test -- --update-snapshots`, review
the regenerated PNGs, then **re-run the full suite until green twice in a row**.
A bulk update can silently skip files, and a bad baseline passes on the update run
and only surfaces later as a phantom regression.

## Conventions

- **`--brand-content-max` (1400px) is the single source of truth** for content
  width. Never hardcode `max-w-[1400px]`; use `max-w-(--brand-content-max)`.
- **The container carries the width, children carry the gutter** - a flat 24px
  (`px-6`). `main` has **no** horizontal padding on purpose; re-adding it
  compounds with any nested `.brand-container`.
- Content needing a readable measure (prose, form fields) caps *inside* the shared
  container and stays **left-aligned**. `mx-auto` on such a block breaks the
  shared edge.
- Focus-visible contract: **`var(--brand-accent)`**, 2px, on all interactive
  elements.
- `dark:` is keyed to `[data-theme="dark"]`, not `prefers-color-scheme`.
- Generated `style.css` is tracked and committed. Rebuild after any class change.
- Class names referenced by JS must stay in markup even when styled by utilities:
  `.project-card`, `.about-box`, `.bubble-exclude`, `.hero-logo`, `.hero-name`,
  `.hero-sub`, `.project-tab`, `.gallery-item`, `.wip-notice`, `.brand-nav*`,
  `.brand-footer*`.
- Agent pointer files (`CLAUDE.md`, `CODEX.md`, `GEMINI.md`, `CURSOR.md`,
  `KILO.md`, `COPILOT.md`, `BLACKBOX.md`) all redirect to `AGENTS.md`. Update
  `AGENTS.md`, not the pointers.

## Agent Guidance

**Read first:** [`../AGENTS.md`](../AGENTS.md) for process and branch policy, this
file for structure, [`../TODO.md`](../TODO.md) for open work,
[`../LOGBOOK.md`](../LOGBOOK.md) (newest-first) for why things are the way they are.

**Do not touch without reading the relevant LOGBOOK entry:**

- `netlify.toml`'s `[build] ignore` rule - a bare `git diff --quiet` with unset
  refs exits 0 and would silently skip **every** build forever.
- `tests/global-setup.js` server ordering and its `stdio: 'ignore'` - piping
  `serve`'s request log deadlocked its event loop once already.
- The `mode: 'serial'` line in `bubbles-exclusion.spec.js`.
- `main`'s zero horizontal padding in `src/css/site.css`.

**Footguns, all of which have actually bitten:**

- **Renaming or retagging an element silently drops it out of the bubble exclusion
  zones.** They match by selector, so an element stops being avoided the moment it
  stops matching - no error, and the visual gate cannot see it (reduced motion =
  no bubbles). This has happened three times: the hero logo when inlined to
  `<svg>`, the Projects rail when restyled `.brand-btn` -> `.project-tab`, and the
  Contact form which never matched at all. When you rename a UI element, check
  `DEFAULT_EXCLUSIONS` in the same change and add a bubble spec case.
- **The theme toggle carries both `id="theme-toggle"` and
  `class="brand-theme-toggle"`, and the ID block wins.** Editing only the class is
  a no-op.
- **The nav has no spare room at 360px.** Fitting the fourth label took the lower
  bound of every clamp plus a 44px toggle cap. A fifth label needs a drawer.
- **`scripts/bubbles.js` and `public/scripts/bubbles.js` are duplicates.** Edit
  the former and copy, or the built site keeps the old behavior.
- **The visual gate cannot catch cross-page misalignment** - it grades each page
  against its own past self, so a permanently misaligned page stays green. Use
  `node scripts/measure-content-widths.js` (exits non-zero on divergence).
- **A green suite is not proof a small visual change shipped.** Tolerance is an
  absolute `maxDiffPixels: 500` floor; verify small changes by cropping the
  baseline or probing computed styles.
- Never write a Tailwind class name into a tracked `.md` expecting it to be inert
  (see the `@source not` rules above).

**Regenerate, don't hand-edit:** `images/og-default.png`
(`node scripts/generate-og-image.js`, needs `npm run dev`), the Mistrust webp
assets (`node scripts/generate-mistrust-assets.js [--all]`), and `style.css`
(`npm run css:build`).
